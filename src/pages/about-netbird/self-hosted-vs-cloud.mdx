# Self-hosted и Cloud NetBird

NetBird можно использовать двумя способами: самостоятельно размещать его (self-hosted) или использовать облачную версию (SaaS). Self-hosted — автономная версия, которую можно установить на собственных серверах, а cloud-hosted — SaaS (Software as a Service), размещённый на серверах NetBird.

Часто возникает вопрос: в чём разница между этими вариантами? Ниже приведён краткий обзор.

## Перед выбором self-hosted NetBird для production

Когда мы создавали NetBird, нашей целью было упростить администрирование сети — избавить администраторов от сложностей с настройкой брандмауэров, открытием портов, управлением VPN-шлюзами, сертификатами и т. д. Мы хотели создать инструмент, который позволяет полностью закрыть сеть от внешнего мира и при этом обеспечивает устройствам автоматическое обнаружение и подключение к внутренним ресурсам после установки клиентских приложений.

Однако за простым интерфейсом скрывается много процессов. NetBird использует набор взаимосвязанных компонентов, которые вместе обеспечивают защищённые peer-to-peer соединения, резервные ретранслируемые соединения через географически распределённые relay-серверы, а также общую надёжность и доступность системы. Надёжно развернуть и обслуживать такую инфраструктуру непросто. NetBird — это не просто один VPN-сервер. Подробнее о работе NetBird можно прочитать [здесь](/about-netbird/how-netbird-works).

## Что нового: внешний IdP больше не требуется

Начиная с версии 0.62 самостоятельное размещение NetBird стало значительно проще. Раньше требовалось отдельно устанавливать и обслуживать identity provider, например Zitadel, Keycloak или Auth0. Теперь Management Service поддерживает **локальное управление пользователями**, поэтому:

- **Внешний IdP не требуется** — пользователей можно создавать и управлять ими непосредственно в NetBird
- **Меньше контейнеров** для развёртывания и обслуживания (4–5 вместо 7+ ранее)
- **Меньше требований к ресурсам** (~1 ГБ RAM вместо 2–4 ГБ ранее)
- **Управление пользователями непосредственно в Dashboard**
- **Внешние IdP по желанию** — можно подключить Google, Microsoft, Okta и другие IdP для SSO
- **Поддержка нескольких IdP** — можно одновременно настроить несколько OIDC-провайдеров

Это делает self-hosted вариант более подходящим для homelab, небольших команд и proof-of-concept развёртываний.

## Установка и обслуживание

Платформа NetBird представляет собой набор [нескольких компонентов](/about-netbird/how-netbird-works), которые позволяют машинам устанавливать прямые point-to-point соединения, а администраторам управлять сетью, например контролировать доступ.

При использовании self-hosted версии вы отвечаете за установку и обслуживание всех компонентов, резервное копирование и защиту данных. Благодаря встроенному локальному управлению пользователями эта нагрузка значительно уменьшилась — больше не требуется поддерживать отдельную инфраструктуру identity provider.

Для cloud-hosted NetBird достаточно установить клиент NetBird на машины и выполнить вход в сеть. Облачная версия больше подходит организациям, которым нужно решение без сложной эксплуатации, которое легко настроить и поддерживать.

## Возможности

Self-hosted и cloud-hosted версии имеют одинаковую базовую функциональность подключения, однако облачная версия содержит дополнительные возможности для бизнес-клиентов, упрощающие автоматизацию и управление сетью:

- **[Provisioning пользователей и групп](/manage/team/idp-sync)** из identity provider (IdP).
- **[Журналирование сетевых событий](/manage/activity/traffic-events-logging)** подключений к внутренним ресурсам для аудита и анализа.
- **[Потоковая передача событий](/manage/activity/event-streaming)** на сторонние платформы и в SIEM-системы (также доступна в self-hosted с [enterprise-лицензией](/selfhosted/enterprise)).
- **[Интеграции с EDR](/manage/access-control/endpoint-detection-and-response)**, например CrowdStrike.
- **[Одобрение peers](/manage/peers/approve-peers)** перед подключением к сети.
- **[Приглашение пользователей](/manage/team/add-users-to-your-network#direct-user-invites)**.
- **[Функциональность MSP](/manage/for-partners/msp-portal)** для управления несколькими tenant-сетями из одного аккаунта.

<Note>

## Географически распределённые Relay-серверы

NetBird использует relay-серверы для установления соединений между машинами, когда прямое point-to-point соединение невозможно.

При использовании cloud-hosted версии доступны географически распределённые кластеры relay-серверов в нескольких регионах мира, что помогает машинам устанавливать соединения. Клиенты NetBird выбирают ближайший relay-сервер.

В self-hosted версии необходимо самостоятельно разворачивать relay-серверы. Это сложная задача, требующая дополнительного обслуживания.

## Высокодоступный Management Layer

В cloud-hosted версии используются высокодоступные серверы control plane (Management), обеспечивающие стабильность критически важной сетевой инфраструктуры.

## Краткое сравнение

| Параметр | Self-hosted | Cloud-hosted |
|--------|-------------|--------------|
| **Время настройки** | ~5 минут с локальными пользователями | Мгновенно |
| **Инфраструктура** | Управляете самостоятельно | Управляет NetBird |
| **Identity provider** | Встроенные локальные пользователи (+ внешние IdP по желанию) | Управляется NetBird |
| **Несколько IdP** | Да, совместимые с OIDC | Да |
| **Relay-серверы** | Один экземпляр (или самостоятельное географическое распределение) | Глобально распределённые |
| **Высокая доступность** | Самостоятельная настройка | Включена |
| **SCIM provisioning** | Enterprise-лицензия | Включено (Business+) |
| **Стоимость** | Стоимость вашей инфраструктуры | Подписка |
| **Подходит для** | Homelab, изолированных сетей, требований compliance | Команд, которым нужна простая настройка |
