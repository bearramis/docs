# Часто задаваемые вопросы

## Какие порты брандмауэра нужно открыть для NetBird?

Клиенту NetBird не требуется открывать какие-либо входящие порты. Полный список исходящих конечных точек, портов и примеров правил брандмауэра для NetBird Cloud приведён на странице [Порты и брандмауэры](/about-netbird/ports-and-firewalls#network-firewall-ports). При самостоятельном размещении см. [требования к портам для self-hosted](/selfhosted/selfhosted-guide#port-requirements).

## Как NetBird взаимодействует с брандмауэром хоста?

NetBird автоматически добавляет правила, разрешающие трафик через интерфейс `wt0` в Windows и Linux. О поведении на разных платформах, распространённых конфликтах (UFW, firewalld, Windows Firewall, стороннее ПО безопасности) и способах устранения проблем см. [Порты и брандмауэры](/about-netbird/ports-and-firewalls#host-based-firewalls).

## Зачем нужны анонимные метрики использования?

### Зачем мы добавили сбор метрик?

Как проект с открытым исходным кодом и бизнес, мы считаем принятие решений на основе данных важным. Сбор анонимных метрик позволяет понимать темпы распространения, использование функций и типы используемых клиентских операционных систем. Мы просим пользователей нашего сообщества по возможности не отключать метрики: это помогает оценивать влияние ошибок и качество программного обеспечения с течением времени.

<Note>
Сбор данных ограничен нашей системой управления.
</Note>

Если сбор метрик нарушает внутренние правила или требования вашей организации, его можно отключить, добавив флаг `--disable-anonymous-metrics=true` в команду запуска Management Service. Интервал по умолчанию составляет 12 часов, но его можно изменить с помощью переменной окружения `NETBIRD_METRICS_INTERVAL_IN_SECONDS`.

### Какие метрики собираются?

Мы собираем следующие метрики:

* Количество аккаунтов, пользователей и сервисных пользователей
* Количество персональных токенов доступа
* Количество peers (всего, с включённым SSH, с включённым сроком действия входа, активированных пользователем)
* Количество активных peers и активных пользователей за последний интервал сбора
* Количество peers по операционным системам (всего и активных)
* Количество UI-клиентов и их операционных систем
* Использование setup keys (включая временные setup keys для peers)
* Количество групп
* Количество маршрутов (включая маршруты с routing groups)
* Количество сетей, сетевых ресурсов и сетевых маршрутизаторов
* Количество правил политик управления доступом (по протоколу и направлению)
* Количество проверок состояния и правил с исходными проверками состояния
* Количество сервисов reverse proxy (всего, включённых, по статусу, типу цели и типу аутентификации)
* Количество сервисных целей (по типу: peer, host, domain, subnet)
* Количество пользовательских доменов (всего и подтверждённых)
* Количество аккаунтов, провайдеров, политик и бюджетных правил Agent Network, а также количество аккаунтов с включённым сбором журналов Agent Network
* Суммарное использование Agent Network (входные токены, выходные токены и стоимость в USD)
* Использование Rosenpass
* Тип IdP Manager и распределение встроенных IdP-провайдеров
* Тип движка хранилища
* Время работы сервиса
* Версия сервиса (включая минимальную/максимальную версии активных peers)
* Время генерации метрик

### UUID метрик

Для каждого Management Service используется идентификатор установки, который создаётся один раз и хранится в базе данных Management Service. Он не содержит сведений о другой личной информации и позволяет различать отдельные развёртывания.

### IP-адрес отправителя метрик

IP-адрес отправителя мы не сохраняем: он отбрасывается после завершения запроса.
